## Corregido

### 1. Autenticación real en las Edge Functions de Google
- **Antes:** solo llevaban `verify_jwt=true` a nivel de gateway de Supabase, lo cual acepta igual la anon key pública que un usuario real.
- **Ahora:** cada función exige un JWT de usuario real vía `supabase.auth.getUser()` (401 si no hay sesión válida), valida tipo/rango del input (400 si es inválido), y aplica timeout de 8s con `AbortController` a la llamada saliente a Google (502 si falla o se cuelga).
- **Commit:** `9f842ed` — "security: exigir usuario autenticado en Edge Functions de Google"
- **Verificado:** con solo la anon key la función ahora devuelve 401 (antes devolvía 200 con datos reales de Google).

## Contexto: rotación de la API key de Google (cerrado antes de este audit)
En la misma revisión se detectó que la clave de Google Places (`AIzaSy...`) estaba hardcodeada en el historial de git del repo público desde julio. Se rotó la clave en Google Cloud Console, se purgó del historial con `git-filter-repo`, y ahora vive solo como secret `GOOGLE_PLACES_API_KEY` en las Edge Functions de Supabase — nunca en el binario de la app ni en el repo.
